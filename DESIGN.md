# Interface contract

The daily-work path is Company → Person → Deal → Discovery → Proposal → explicit Won decision → Delivery. Tasks name an owner, due time and linked record. Every record opens into a focused editor; saved versions survive refresh. Pending, failed, read-only, empty and uncertain outcomes need distinct visible states.

Use a restrained dark surface hierarchy, readable system typography, consistent spacing, half-pixel borders with 80 percent color alpha, 44px controls and visible keyboard focus. The reusable patterns are Page heading, Status, Work summary, Record tabs, Record list, Record editor and Error recovery. Tokens live in web/styles.css. Record labels are text, never HTML.

A status describes evidence, not intent. Won requires a human decision; a draft proposal is not a contract; delivered milestones are not customer endorsements. After an uncertain write, close and refresh to inspect the stored version before another change. No marketing claim should imply client results, automatic scheduling or continuous monitoring.
